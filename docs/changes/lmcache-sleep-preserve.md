# Status: Preserve LMCache through supported engine sleep — 2026-11-11 (branch `feat/lmcache-sleep-preserve`)

Owner decision of 2026-11-11, item 4 option A, amends ADR 0034: the launch-time source check recognizes vLLM's preserving sleep query and the scheduler's conditional connector reset, and SGLang's non-clearing LMCache release/reset path. With active LMCache, recognized vLLM installations send `POST /sleep?level=N&reset_connector=false`. Unrecognized or clearing installations retain `sleep_clears_cache`: required launches refuse and auto leaves LMCache off. The vLLM 0.32/0.33 guard remains; no upstream Python reset semantics are patched.

The wake checkpoint checks enforce unchanged weights (ADR 0014 §7): the local checkpoint gate and the enrolled host verify the recorded digest before restoration, and a supplied replacement digest cannot override it. Adopted local LMCache sleep-parking runtimes now also use the existing checkpoint gate. Loopback-only controls and per-launch key guards are unchanged. No protocol field or qualified-table row is added. The live harness prepares a fresh vLLM 0.34.0rc1 environment and builds LMCache 0.5.7 against that engine's own torch, without build isolation and with engine constraints. LC13–LC16 use full qualification on preserving vLLM and SGLang installations; vLLM 0.33 remains a guard check.

The new setup keys are `VLLM_034=$V020/engines/vllm-0.34.0rc1-venv` and `LMCACHE_VLLM_034=$V020/engines/vllm-0.34.0rc1-lmcache057-venv` (`$V020` defaults to `~/capyctl-v020`). Existing `LMCACHE` remains the vLLM 0.33 guard environment; `LMCACHE_SGLANG` supplies SGLang 0.5.23 qualification. Overrides name existing read-only installations, not permission to modify them.

T45 tests cover versioned real-source shapes, the sleep query, and LMCache mode outcomes. CPU and Fake-engine tests are not qualification. The new environments have not been installed or exercised live by this change; the full LC13–LC16 correctness, store-race, footprint, wake-canary and latency bounds must pass before any combination enters `QUALIFIED_PARKING`.

Verification used `CARGO_BUILD_JOBS=8`: `cargo fmt --all`; all-target tests for adapters, agent and controller; and all-target config tests. The first broad Rust run exposed three existing restart-park tests failing because the new retained-driver check also required sleep preservation for `restart_only`. Restricting that check to sleep-based residencies restored all 36 native-vLLM tests; the other Rust suites had passed. Config tests passed (668 tests), the live-harness pytest suite passed (63 tests), and setup shellcheck passed. Workspace clippy with `-D warnings` is blocked by an unrelated existing `unused_io_amount` in `crates/capyctl-adapters/src/forward.rs:1951`; no warning was suppressed. Runtime Python files are unchanged.

# Release note: Memory

- **Keep LMCache across supported sleep paths.** CapyCTL recognizes vLLM's external-cache-preserving sleep API (introduced in 0.34.0rc1) and SGLang 0.5.23's non-clearing reset by installed source shape. Older or unrecognized paths keep the safety guard. These combinations remain uncertified until their live parking rows pass.
